# クライアント要件定義

レビュー反映日: 2026-10-24。更新後のMVPではRaspberry Pi 4が音声入出力とサーボを担当し、AndroidスマートフォンはWeb上の操作・設定・状態表示を担当する。アプリサーバーがSTT・LLM・TTSを処理する。デバイスAPIと実機確認は未完了。

## 1. 役割と対象

Androidスマートフォンのブラウザーで利用するWebアプリを基本とし、HTML・CSS・JavaScriptは `ServerSide/web/` に置いてサーバーから配信する。画面は設定、Irodori-TTSの参照WAV管理、会話開始／停止、デバイス状態表示を担当する。Raspberry Pi 4がマイク録音・音声再生・しっぽ駆動を行い、アプリサーバーがSTT・LLM・TTSとセッション管理を行う。

```text
Pi 4のマイク → アプリサーバーのSTT・LLM・TTS → Pi 4のスピーカー
スマホの設定・操作 → アプリサーバー → MCP／デバイスAPI → Raspberry Pi 4 → しっぽ
```

スマホはアプリサーバーに接続する。LM Studio・TTS・Pi 4デバイスAPIの秘密情報はサーバー側で保持する。Pi 4とアプリサーバー間の音声転送はHTTPSを使い、音声は既定で保存しない。

## 2. MVP必須要件

| ID | 要件 | 確認する動作 |
| --- | --- | --- |
| CL-01 | 接続先と準備状態を表示する | スマホ→サーバー、Pi 4のマイク・スピーカー・しっぽの状態を区別し、API接続だけで機器正常と表示しない |
| CL-02 | ユーザー操作で会話を開始する | サーバーがPi 4の音声デバイスを確認し、開始受理後に録音可能状態になる。未接続・機器故障・二重開始を扱う |
| CL-03 | Pi 4で録音しサーバーへ送信する | 録音中を表示し、合意した形式・長さ・容量内の音声だけを現在のセッション／発話に関連付け、HTTPSで送る |
| CL-04 | Pi 4で相づちと本返答を再生する | 音声／発話／停止世代を付けて再生開始・完了・失敗・停止をサーバーへ通知する。配信受付と再生完了を区別する |
| CL-05 | 停止操作を常に使えるようにする | Pi 4の録音・再生・予約としっぽを直ちに止め、LLMの回答を待たずサーバーの停止処理へ要求する |
| CL-06 | 停止後の古い結果を捨てる | 終了済みセッションや停止前の発話に対する相づち・返答が遅れて届いても再生せず、しっぽ開始を再送しない |
| CL-07 | 音量としっぽ設定を変更する | Pi 4のスピーカー音量、トントンの有効／無効・速さを扱う。送信中／反映済み／失敗を分け、サーバーの確認値で反映完了とする |
| CL-08 | 処理状態と失敗を表示する | 未接続、準備中、録音中、送信中、認識中、返答待ち、再生中、停止中、停止済み、エラーを識別できる |
| CL-09 | 切断・復帰を扱う | 切断時は新しい録音送信と再生を止める。再接続後は現在状態を取得し、ユーザー操作で再開する。古い音声・動作を自動再送しない |
| CL-10 | Pi 4の音声機器状態を扱う | マイク・スピーカー未接続、録音失敗、再生失敗を表示し、利用可能と誤表示しない |

トントンの「有効」は動作の許可設定であり、直ちに動作を始める操作とは区別する。MVPの開始条件はユーザーの明確なトントン要求とし、会話開始だけでしっぽを動かさない。開始方法を拡張する場合はサーバー側の許可条件も同時に更新する。

## 3. 相づちと再生制御

- 相づちは必須。サーバーが現在の発話に対応する音声を用意し、Pi 4の再生キューで本返答と調停する。
- ユーザーの発話中、録音中、本返答の再生中には相づちを再生しない。1往復につき最大1回とする。
- 本返答が先に再生可能になった場合は相づちを省略する。開始済み相づちと本返答を重ねない。
- 停止・切断・セッション終了後は、再生中・待機中の相づちと本返答を停止・破棄する。
- 相づちにも音量設定を適用し、同じ言葉の連続使用を避ける。待ち時間と候補音声は実機調整対象とする。

## 4. 手動停止と「おやすみ」

手動停止と異常停止では、最後の返事を待たずPi 4の再生・録音としっぽを停止する。サーバーからPi 4へ停止を要求する。機器の停止結果を確認できない場合は「停止未確認」と表示し、ボタンを押しただけで「機器停止済み」にしない。

通常の「おやすみ」は会話の終了要求として扱い、短い最後の返答を再生してから録音待ちを終了する。この間の新しい相づち・しっぽ開始は許可しない。手動停止が入れば最後の返答も取り消す。

## 5. ブラウザーと配信

スマートフォンの画面はサーバーとPi 4のデバイスAPIへHTTPSで接続する。ブラウザーでマイク・スピーカー権限を取得せず、音声機器の準備・録音・再生状態はPi 4から確認する。

画面ロック・バックグラウンドで会話を継続する要否は未確定。暫定運用は画面表示中とし、背景移行時はサーバー経由でPi 4の録音・再生としっぽを停止する。要求が届かない場合もサーバー／Pi 4側の期限で動作が止まる。復帰時は状態確認後に手動で再開する。

## 6. サーバーとの契約

サーバー側の [外部インターフェース要件](../ServerSide/REQUIREMENTS.md#6-クライアントとの契約) に従う。ダッシュボードの設定読込・保存APIは `GET`／`PUT /api/v1/dashboard/settings` とする。音声会話の開始・停止・状態取得・音声送信・音声受信／状態通知のURLと通信方式は未確定。クライアントへサーバー上の任意ファイルパスやサービス用APIキーを渡さない。

参照音声は `PUT /api/v1/dashboard/reference-audio` を使い、PCM WAVの形式・長さ・サイズをサーバー側で検証する。参照音声の保存先パスはクライアントに指定させない。

## 7. 統合前に確定する事項

| 未決事項 | 完了条件 |
| --- | --- |
| 対応するAndroid機種・OS・ブラウザーの範囲 | Pi 4音声入出力を含むWeb操作を対象実機で確認 |
| 画面ロック・バックグラウンド | 継続会話の要否を決め、必要なら実機で継続・停止・復帰を確認。未確認の間は前面表示でデモする |
| 録音の開始／終了操作 | Pi 4で手動録音または発話区切りを決定。MVPは1往復ずつ処理し、録音中の再生による回り込み対策も確認 |
| 音声形式、長さ・容量上限 | Pi 4の録音形式とサーバーデコード、TTS再生形式の共通仕様を記録 |
| 配信URL・接続方式・認証 | Pi 4／サーバー／スマホ間のHTTPS接続を確認し、開始・停止・設定・音声転送の契約を記録 |
| 応答・停止・接続監視の期限 | 数値をサーバー・機器側と共通化し、期限超過時の表示と停止を確認 |
| 相づちの待ち時間と切替 | 本返答の到着順にかかわらず重複しないことを確認 |

## 8. 受け入れ条件

以下は未実施。機能一覧や画面表示だけで合格にせず、対応するサーバー／実機結果を記録する。

| ID | 確認内容 |
| --- | --- |
| CT-01 | Pi 4のマイク・スピーカーを検出し、録音・再生表示が実際の状態に一致する |
| CT-02 | Pi 4で音声1往復と相づちを再生でき、相づち・発話・本返答が重ならない |
| CT-03 | 認識中・LLM処理中・相づち中・本返答中に停止し、Pi 4で遅着音声・動作を開始しない |
| CT-04 | しっぽの無効化と設定の反映確認が一致し、停止未確認を停止済みと表示しない |
| CT-05 | 切断・再接続・画面復帰後に古い音声や動作を再開しない |
| CT-06 | 「おやすみ」の最後の返事と、手動停止による即時無音を区別できる |
| CT-07 | Androidブラウザーからサーバー内の設定画面を開き、権限がある場合に設定を保存・再読込できる |
| CT-08 | Androidブラウザーから許可されたPCM WAVを参照音声として保存・削除でき、非対応形式や大きすぎるファイルは理由を表示して拒否する |

声・キャラクター・自発的に話す頻度の詳細設定、睡眠時間表示、通知、2台連携は拡張対象とする。
