# クライアント要件定義

レビュー反映日: 2026-10-24。Android Web MVPではスマートフォンが録音・再生、設定・操作、サーバー状態表示を担当する。アプリサーバーがSTT・LLM・TTS・セッション管理に加え、相づちの選択・生成準備・配信判断とPi 4しっぽ制御を担当する。Androidは相づちを生成・選択せず、Pi 4へ直接接続しない。Debug APKのHWV33への導入・起動とAndroid Studioのデバッガー接続を確認したが、WebView・音声機能の実機確認は未完了。

## 1. 役割と対象

AndroidアプリはWebViewを基本とし、HTML・CSS・JavaScriptは `ServerSide/dashboard/web/` に置いてサーバーから配信する。画面は設定、Irodori-TTSの参照WAV管理、会話開始／停止、スマートフォンでの録音・再生を担当する。アプリサーバーがSTT・LLM・TTSとセッション管理を行う。Raspberry Pi 4が担う場合は、しっぽ等の機器制御を別経路にする。

```text
Android WebViewのマイク → アプリサーバーのSTT・LLM・TTS → Android WebViewのスピーカー
スマホの設定・操作 → アプリサーバー → MCP／デバイスAPI → Raspberry Pi 4 → しっぽ
```

スマホはアプリサーバーにHTTPSで接続する。LM Studio・TTS・Pi 4デバイスAPIの秘密情報はサーバー側で保持する。録音はブラウザーからサーバーへ直接送り、音声は既定で保存しない。

## 2. MVP必須要件

| ID | 要件 | 確認する動作 |
| --- | --- | --- |
| CL-01 | 接続先と準備状態を表示する | スマホ→サーバー接続、ブラウザー音声権限、Pi 4しっぽ機器の状態を区別し、API接続だけで機器正常と表示しない |
| CL-02 | ユーザー操作で会話を開始する | サーバーの会話セッションを開始し、マイク権限とブラウザー音声APIを確認する。未接続・権限拒否・二重開始を扱う |
| CL-03 | スマホで録音しサーバーへ送信する | 録音中を表示し、合意した形式・長さ・容量内の音声だけを現在のセッション／発話に関連付け、HTTPSで送る |
| CL-04 | サーバーから届く相づちと本返答をスマホで再生する | 相づちの選択・生成準備・配信判断はサーバーが担当する。Androidはサーバーの再生指示に従い、録音中に重ならないよう音声を再生して再生結果を通知する。現行コードは本返答だけで、相づち配信と再生結果通知は未実装 |
| CL-05 | 停止操作を常に使えるようにする | Androidはスマートフォンの録音・再生を直ちに止め、LLMの回答を待たずサーバーへセッション停止を要求する。しっぽ停止はサーバーが独立経路でPi 4へ要求し、Androidは機器の停止確認状態を表示する |
| CL-06 | 停止後の古い結果を捨てる | 終了済みセッションや停止前の発話に対する相づち・返答が遅れて届いても再生せず、しっぽ開始を再送しない |
| CL-07 | 音量としっぽ設定を変更する | Androidの音量操作と、サーバーへ送るトントンの有効／無効・速さ設定を扱う。しっぽ要求の許可判定・MCP実行・Pi 4への接続はサーバー側で行う。設定は送信中／反映済み／失敗を分け、サーバーの確認値で反映完了とする。現行Web画面にアプリ内音量設定は未実装 |
| CL-08 | 処理状態と失敗を表示する | 未接続、準備中、録音中、送信中、認識中、返答待ち、相づち／本返答の再生中、停止中、停止済み、しっぽ機器状態、エラーを識別できる。機器状態はサーバーの確認結果に基づき、AndroidがPi 4への接続を独自に判定しない |
| CL-09 | 切断・復帰を扱う | 切断時は新しい録音送信と再生を止める。再接続後は現在状態を取得し、ユーザー操作で再開する。古い音声・動作を自動再送しない |
| CL-10 | スマホの音声権限と状態を扱う | マイク拒否、入力デバイスなし、録音失敗、再生失敗を表示し、利用可能と誤表示しない |

トントンの「有効」はサーバー側の動作許可設定であり、直ちに動作を始める操作とは区別する。開始条件はユーザーの明確なトントン要求とし、会話開始だけでしっぽを動かさない。Androidは要求と設定をサーバーへ送り、サーバーが許可条件を検証してMCP経由でPi 4を制御する。AndroidはMCPやPi 4デバイスAPIを直接呼び出さない。

## 3. 相づちと再生制御

- 相づちの発生判断、候補選択、音声の生成準備、対象発話への関連付け、配信・取消はサーバーが担当する。Androidは届いた音声を出力する。
- Androidの再生キューはサーバーの優先順位・取消通知に従い、本返答や録音と音声を重ねない。現行Web APIでは相づち配信と再生結果通知は未実装。
- ユーザーの発話中、録音中、本返答の再生中には相づちを再生しない。1往復につき最大1回とする。
- 本返答が先に再生可能になった場合は相づちを省略する。開始済み相づちと本返答を重ねない。
- 停止・切断・セッション終了後は、再生中・待機中の相づちと本返答を停止・破棄する。
- Androidの端末音量を相づちにも適用する。同じ候補の連続使用を避ける処理と待ち時間・候補音声の決定はサーバー側で行い、実機調整する。

## 4. 手動停止と「おやすみ」

手動停止と異常停止では、Androidが最後の返事を待たずスマートフォンの録音・再生を止めてサーバーへセッション停止を要求する。サーバーはPi 4へ独立に停止を要求する。Androidはサーバーから機器状態を受け取り、停止結果を確認できない場合は「停止未確認」と表示する。ボタンを押しただけで「機器停止済み」にしない。

通常の「おやすみ」は会話の終了要求として扱い、短い最後の返答を再生してから録音待ちを終了する。この間の新しい相づち・しっぽ開始は許可しない。手動停止が入れば最後の返答も取り消す。

## 5. ブラウザーと配信

AndroidアプリのWebViewは、同一LocalNET内にあるServerSideのURLを開き、最後に使ったURLを次回起動時に復元する。具体的なURLは運用設定時に確定する。マイク利用にはAndroidの録音権限とブラウザーの権限が必要で、`getUserMedia()` のためHTTPSなどの安全なコンテキストを使う。音声形式は `MediaRecorder.isTypeSupported()` で対応する形式を選ぶ。

画面ロック・バックグラウンドで会話を継続する要否は未確定。暫定運用は画面表示中とし、画面離脱時は端末の録音・再生とサーバー会話を停止する。復帰時は状態確認後に手動で再開する。

## 6. サーバーとの契約

サーバー側の [音声会話API契約](../ServerSide/VOICE_API.md) と [外部インターフェース要件](../ServerSide/REQUIREMENTS.md#6-クライアントとの契約) に従う。セッション開始、Raw audio upload、期限付き返答音声取得、DELETE停止を実装した。入力はWebM/Ogg/WAV/MP4、最大25MB・60秒で、管理Bearer tokenを使う。クライアントへサーバー上の任意ファイルパス、サービス用APIキー、Pi 4接続情報を渡さない。相づち配信・再生結果通知と、サーバー経由のしっぽ操作APIは未実装。

参照音声は `PUT /api/v1/dashboard/reference-audio` を使い、PCM WAVの形式・長さ・サイズをサーバー側で検証する。参照音声の保存先パスはクライアントに指定させない。

## 7. 残作業・端末統合前の確認

| 確認対象 | 現在の状態 | 残る確認 |
| --- | --- | --- |
| Android機種・OS・WebView | Windows上でDebug APKをビルドし、Android 10（API 29）のHWV33にインストールして`MainActivity`起動を確認。Android Studioから実行中プロセスへのデバッガー接続も確認 | WebViewでHTTPS接続、録音→送信→返答再生→停止を実機確認 |
| 画面ロック・バックグラウンド | 暫定運用は画面表示中。画面非表示で端末音声を止め、セッション終了を要求するコードを追加 | 対象端末で画面ロック・アプリ切替時の停止と、復帰後に手動再開できることを確認 |
| 録音操作 | 手動録音・停止と最大60秒のコードを実装 | 対象端末で権限、録音上限、録音中の再生回り込みを確認 |
| 音声形式・容量 | API契約はWebM/Ogg/WAV/MP4、25MB・60秒 | 実端末の録音形式、サーバーデコード、TTS音声再生を確認 |
| HTTPS・認証 | Android接続先はHTTPS限定、APIは管理Bearer tokenを使用 | HTTPS終端、設定・音声APIへの接続、認証の実端末確認 |
| 応答・停止 | サーバー総処理期限は180秒。端末側の停止処理を実装 | 実応答時間、停止競合、切断・再接続を確認 |
| 相づち | 候補選択と音声事前準備はサーバー側にあるが、Android Webへの配信・再生通知は未実装 | サーバーが発話・停止世代に応じて配信・取消を判断し、Androidで再生・完了通知まで確認 |
