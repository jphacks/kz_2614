# サーバー要件定義

レビュー反映日: 2026-10-24。Android Web MVPではスマートフォンが録音・再生、サーバーがSTT・LLM・TTSと会話セッション管理を担当する。Raspberry Pi 4のAPI契約はしっぽ等の機器連携用に保持するが、Android Webの音声入出力経路には接続しない。必要な動作と実装状況を分けて記載する。

既存のWhisper→LM Studio→Irodori-TTSパイプラインに、Android Web向けの音声アップロード、セッション、返答音声取得、停止世代のAPIコードを追加した。Web画面とAndroid WebViewも追加したが、モデル・HTTPS環境・Android実機での接続は未確認であり、MVP受け入れ完了とは扱わない。相づち配信・再生完了通知・Pi 4デバイスAPIとの統合は未実装。

## 1. 役割

```text
Android WebViewのマイク → POST音声 → Whisper(STT) → LM Studio(LLM)
Android WebViewのスピーカー ← GET音声 ← Irodori-TTS ← 返答テキスト
                                                 LLM → MCP → Pi 4デバイスAPI → サーボ
Android WebViewの設定・操作 → アプリサーバー
```

サーバーが会話セッションと設定の正本を持つ。Android WebViewがブラウザーのマイク録音・スピーカー再生を行い、サーバーはSTT・LLM・TTSを処理する。しっぽを接続する場合は、MCPが限定されたトントン要求だけを受け、GPIOやサーボ角度を直接公開しない。

## 2. セッション・停止

| ID | 必須要件 |
| --- | --- |
| SV-01 | 開始・状態取得・終了を提供し、会話履歴と処理結果をセッションごとに分離する。セッション／発話識別子と、停止前後を識別する世代または同等の仕組みを持つ |
| SV-02 | 同一セッションの発話は1往復ずつ処理する。二重送信・二重開始を検出し、過剰な要求を無制限にキューへ貯めない。並行数・待ち行列上限と過負荷応答を決める |
| SV-03 | 停止要求はSTT・LLM・TTSの完了や会話ロックを待たず受理し、音声配信・相づち予約・新しいしっぽ動作を無効化する |
| SV-04 | 停止した世代の遅着結果を配信・実行しない。外部処理を中断できない場合も、その結果は破棄する。再接続・再起動時に古い要求を再実行しない |
| SV-05 | しっぽ停止をLLMの判断から独立した制御経路で送る。要求送信、機器の受理、停止状態の確認を区別し、未確認を停止済みと返さない |
| SV-06 | 接続監視・セッション期限・動作タイムアウトを持ち、切断時は新しい動作を許可しない。復帰後は状態確認と明示的な再開が必要 |

「おやすみ」は通常の会話終了として、短い最後の返答だけを許可してから終了する。Android Web UIでの再生完了通知は未実装のため、現在は手動停止とターン単位の返答再生までを実装対象とする。失敗・期限切れも扱い、終了待ちを無制限に続けない。この間の新しい相づち・しっぽ開始は抑止する。手動停止・異常停止では最後の返答も取り消す。

## 3. STT・LLM・TTS

| ID | 必須要件 |
| --- | --- |
| SV-07 | 合意した音声形式だけを受信し、長さ・容量を制限してWhisperへ渡す。スマホに任意のサーバーファイルパスを指定させない。非対応形式・破損データ・無音を明示的に扱う |
| SV-08 | 空の文字起こしではLLMやしっぽ開始へ進まない。認識に失敗した発話から動作指示を推測しない。日本語での小声の認識は実機確認する |
| SV-09 | Whisperの文字起こし全文を今回のユーザー発話（質問・依頼）としてLM Studioの `input` に明示し、過去の会話は別の文脈として渡す。質問本文をシステム指示や過去の履歴だけに置かず、空の文字起こしは送らない。処理が正常完了したターンは上限付き会話履歴へ追加する。短く自然な日本語の返答を要求し、出力上限を持つ。思考文を読み上げず、`reasoning=off` 非対応は明示的なエラーにする |
| SV-10 | 返答テキストをTTSへ渡し、Androidブラウザーが再生できる形式で配信する。設定した声を使用し、合成失敗を成功として扱わない |
| SV-11 | STT・LLM・TTS・初回音声準備・配信・全体の所要時間を区別して測定する。各段階と会話全体に期限を設け、超過時は処理状態を終了させて通知する |

Whisper・LLM・TTSのモデル、デバイス、バージョンと設定を記録する。メモ記載のモデル名は候補で、採用・性能は実機結果で確定する。初回ダウンロードやモデルロード時間は通常の会話遅延と分け、デモ前に必要ファイルを取得して準備状態を確認する。

### 質問・依頼本文の受渡し仕様

1. `WhisperSTT.transcribe_file()` が音声から認識した本文を `Transcription.text` に返す。
2. `VoicePipeline.process_audio_file()` は空本文なら `NoSpeechDetected` とし、LLM・TTSへ進まない。
3. 本文がある場合は `VoiceLLMClient.generate_response(transcription.text, history)` に渡す。`app/voice/llm.py` がLM Studioの `input` 内に「今回のユーザー発話（質問・依頼）」として本文を配置する。
4. 直近の会話履歴は同じ `input` 内で「以前の会話」として分離し、今回の発話に答えるための文脈として使う。話し方や役割の指定は `system_prompt` に置き、質問本文はそこへ入れない。
5. 生成された返答本文をTTSへ渡し、音声バイト列と形式を `VoiceTurnResult.speech` で返す。

この経路では質問本文をファイルやログへ保存しない。会話履歴は `VoicePipeline` インスタンスのメモリ内だけに保持する。

現行コードの初期設定と実装境界は次のとおり。実行時の有効値は環境設定とモデルサービス側でも確認する。

| 段階 | 現行の初期設定 | 入出力・制約 | 未確認事項 |
| --- | --- | --- | --- |
| STT | `Systran/faster-whisper-small`、日本語、CPU / int8、モデルキャッシュ `ServerSide/whisper/` | Android WebからのWebM/Ogg/WAV/MP4音声を読み、既定25,000,000バイト・60秒以下を `Transcription` に返す。空結果はLLMへ渡さない | ブラウザーごとの録音形式、日本語の小声認識、実モデルの性能 |
| LLM | `http://127.0.0.1:1234/api/v1/chat`、`google/gemma-4-26b-a4b`、最大160トークン、context 4096、履歴最大8メッセージ、45秒HTTP timeout | `reasoning=off`、`store=false`。現在の発話は `input`、役割指示は `system_prompt`。空本文とreasoning出力はエラー | 指定モデルの稼働、LM StudioのAPI互換性・実応答 |
| TTS | `http://127.0.0.1:7861/`、`Aratako/Irodori-TTS-600M-v3-VoiceDesign`、model / codec は CUDA・fp16 | Gradio `/_run_generation` に返答本文を渡し、既定25,000,000バイト以下の音声とmedia typeを返す。一時結果ファイルはOS一時フォルダー内にある場合、読込後に削除 | サーバー・モデルの配置、GPU/CPU対応、応答時間、Android WebViewでの再生形式 |

具体的な変更値は `ServerSide/app/.env.example` を参照する。WhisperとTTSには段階timeoutがなく、HTTP全体期限を超えた場合は会話セッションを破棄する。個別サービスの取消・時間測定は未完了。

## 4. 相づち（MVP必須）

| ID | 必須要件 |
| --- | --- |
| SV-12 | 認識済み発話への返答待ちが設定時間を超える場合、短い相づち音声を1往復につき最大1回用意する。事前生成・キャッシュを実現方法の候補とする |
| SV-13 | 相づち／本返答にセッション・発話・停止世代を関連付け、Androidクライアントが重複・遅着・終了済み音声を除外できるようにする。実際の再生担当はAndroid端末に限定する |
| SV-14 | 本返答が先に再生可能になれば相づちを取り消す。相づち中に本返答が準備できた場合も重ならないよう再生を調停する。停止・切断で予約と配信を取り消す |
| SV-15 | 相づちと本返答に同じ声を使用し、Androidの再生音量設定を使う。サーバーで二重に音量補正しない。同じ相づちの連続使用を避け、発話中や「おやすみ」終了処理中に追加しない |

現行コードの相づち候補は「うん、聞いてるよ。」「そっか、話してくれてありがとう。」の2種類で、`VOICE_ACK_DELAY_SECONDS` の初期値は0.9秒。会話開始前に同じTTS設定で音声をメモリへ準備し、候補を交互に選ぶ。LLMが先に返答した場合は省略し、しきい値を超えた場合は非同期コールバックへ一度だけ渡す。現在のAndroid Web音声APIは相づちを配信しないため、ブラウザーへの再生経路は未実装。0.9秒、文言、声、音量は仮設定であり、実機で調整する。

## 5. MCP・しっぽ

| ID | 必須要件 |
| --- | --- |
| SV-16 | `tap_tail`・`stop_tail`・`get_tail_status` だけを会話用に公開する。自由なサーボ角度・任意URL・任意ツール実行は受け付けない |
| SV-17 | しっぽ開始時に、現在のセッションが動作中で、設定が有効で、明確な要求があり、停止後の古い要求ではないことを制御側で確認する。プロンプトだけを許可判定にしない |
| SV-18 | LM Studio内部で遅れてMCPが実行される場合も、MCP／機器側の許可確認で停止済みセッションの開始を拒否する。外部HTTP要求の取消だけで停止を保証しない |
| SV-19 | 期間・速さ・連続動作量を制限する。短い操作の連続要求で上限を無制限に延長しない。Raspberry Pi 4側にも角度・速度・時間の制限を持たせる |
| SV-20 | HTTP成功、機器の受理、実動作／停止状態を区別する。不正JSON、未知の状態、接続失敗は機械判定可能な失敗として返し、成功を示す会話に使わない |
| SV-21 | 機器用トークン、接続先と動作許可はサーバー設定で管理する。トントン設定の無効化は処理中の動作にも適用し、停止操作は開始許可が無効でも実行可能にする |

既存の0.5〜5秒・毎秒0.3〜1.0回というMCP引数制限はソフトウェア側の暫定上限で、しっぽの重さ・力・接触位置・騒音・発熱の確認済み範囲を示さない。Pi 4との音声・制御APIのMVP契約は [Raspberry Pi 4 API仕様](RASPBERRY_PI_API.md) に定める。デバイスサービス、アプリセッション／停止世代の連携、遅着開始の拒否と実機確認は未完了であり、有効化条件として残す。

## 6. クライアントとの契約

Android Web向けの音声API契約は [VOICE_API.md](VOICE_API.md) に記録し、開始・状態・発話アップロード・返答音声取得・停止のコードを追加した。設定ダッシュボードAPIと同じ管理トークンを使う。サーバー起動、モデル接続、HTTPS、端末接続、受け入れ確認は未実施。

| 論理操作 | 入力・結果として必要な情報 |
| --- | --- |
| `GET /api/v1/voice/status` | 音声APIの制限と同時セッション数。モデルサービスの稼働確認とは分ける |
| `POST /api/v1/voice/sessions` | 会話セッションID、停止世代、期限 |
| `POST /api/v1/voice/sessions/{session_id}/turns/{turn_id}` | スマートフォンから音声本文をraw upload。形式・長さ・容量、受理／BUSY／拒否を検証 |
| `GET /api/v1/voice/sessions/{session_id}/turns/{turn_id}/audio` | 対象セッション・発話・停止世代の返答音声を期限付きで取得 |
| `DELETE /api/v1/voice/sessions/{session_id}` | セッション停止、世代更新、未取得音声の破棄。端末のローカル録音／再生はクライアントが停止 |
| 設定変更 | ダッシュボードは設定JSONを返す。保存成功・拒否を返し、新規音声処理インスタンスへの反映を表示する。音声セッションAPIの設定変更通知・版管理は未実装 |
| TTS参照音声 | PCM WAVのアップロード・状態取得・削除。保存先はサーバー固定パスとし、クライアントからファイルパスを受け取らない |
| 再生結果通知 | Webクライアントの再生開始・完了・失敗通知は未実装。現在は受信と再生完了を区別していない |
| 停止・終了 | 対象セッション、停止世代、サーバー側の停止受付とAndroid端末のローカル停止を区別する。Pi 4機器の停止確認は別契約 |

失敗は種類・再試行可否・対象要求を返す。切断後に同じ要求が来ても発話を二重処理しない。Android Webの入力形式はWebM/Ogg/WAV/MP4、最大25,000,000 bytes・60秒、返答音声URLの保持は2分。音声の形式署名を確認し、STTのデコード後時間も60秒以下か検査する。状態の受け渡しだけでAndroidの再生やPi 4機器動作を証明したことにしない。

## 7. 設定・データ・起動

- `web/` の設定ダッシュボードで、STTモデル・言語・デバイス・計算形式・VAD、TTSモデル・声の説明、会話の話し方・返答長・質問頻度を設定できる。設定読込・保存は `GET`／`PUT /api/v1/dashboard/settings` とし、値を検証して `app/data/dashboard_settings.json` に保存する。
- TTSの参照音声としてPCM WAVを `PUT /api/v1/dashboard/reference-audio` でアップロードし、`GET` で状態確認、`DELETE` で削除できる。サーバー内の固定先 `app/data/reference_voice.wav` へ検証後に原子的に保存し、元のファイル名やクライアント指定パスは保存先に使わない。形式は16-bit PCM、mono/stereo、16〜48kHz、長さ1〜30秒、サイズ10MB以下に制限する。
- アップロードWAVは次に作る `IrodoriTTS` インスタンスの `ref_wav` として使う。インスタンス生成時に音声をメモリへ読み込み、保存音声の置換・削除後も進行中インスタンスは元の音声を使い続ける。音声は設定JSON・Git・ログに含めず、TTS生成時に設定されたIrodori-TTSサーバーへ送る。その他の音声形式は未対応。
- 保存したSTT・TTS設定は、新しく作る音声処理インスタンスに反映する。会話のふるまい設定は安全ルールを変えない話し方の希望としてシステムプロンプトに加える。現在進行中の会話への動的変更は行わない。
- 相づちは必須のため、画面・APIのどちらからも無効化できない。ダッシュボードからMCP制御を有効化しない。しっぽの制御許可と停止規則はサーバー側の既存ゲートに従う。
- ダッシュボードサーバーは既定で `127.0.0.1` にだけbindする。loopback外で起動する場合は `NENGITSUNE_DASHBOARD_TOKEN` を必須とし、管理APIはBearer認証する。LAN公開には信頼できるネットワークとHTTPS終端が必要。
- APIキーや機器トークンはサーバーの環境設定で管理し、ブラウザー、Git、ログ本文へ出さない。Android Web音声APIは管理Bearer tokenで保護し、端末接続にはHTTPSを使う。Pi 4との制御APIは別途HTTPSとデバイス認証を使う。
- 音声アップロードの一時データは必要最小限とし、成功・失敗後に削除する。返答音声はメモリ内で最大2分、停止・期限切れで削除する。履歴はセッションのメモリ内で上限を持ち、終了時に消去する。本文をログへ残す場合は明示的な設定を必要とする。
- `store=false` はLM Studioへの保存無効の要求であり、関連サービスのログ・一時データ管理も確認する。
- 起動時にモデル・実ファイルパス・LM Studio・TTS・MCP・機器の準備を確認し、利用不可の機能をスマホへ返す。再起動だけで動作を自動再開しない。
- 自作は `app/`、外部ソースは `third_party/`、モデルの配置はコード設定と実ディレクトリが一致するよう管理する。
- ダッシュボード設定はサーバーにのみ保存し、秘密情報、録音音声、会話本文は設定JSONへ含めない。ユーザー入力は長さ・選択肢を検証する。
- 参照音声ファイルはユーザーが明示的に登録したWAVだけを保存する。置換・削除できるようにし、保存ファイルをGitやログへ含めない。

| ST-07 | 成功・停止・失敗で一時音声と履歴が方針どおり削除され、ログに秘密情報を残さない |
| ST-08 | ダッシュボード設定をサーバーへ保存・再読込でき、不正な値を拒否する。新しい処理インスタンスに設定が反映され、相づち必須が守られる |
| ST-09 | 有効なPCM WAVだけを制限内で保存し、破損・形式違い・長さ超過・過大ファイルを拒否する。置換・削除後も既存TTSインスタンスの参照音声が変化せず、新規インスタンスでは現在のWAVになる |
