# サーバー要件定義

レビュー反映日: 2026-10-24。MVPはスマホで録音・再生し、サーバーがSTT・LLM・TTS・相づちの生成／配信と、MCP経由のしっぽ制御を担当する。必要な動作と実装状況を分けて記載する。

現状は音声ファイル→Whisper→LM Studioの呼び出し部品とMCPサーバーがある段階。スマホ向けAPI、TTS、音声配信、相づち、セッション停止を含む統合は未実装・未検証であり、MVP受け入れ完了とは扱わない。

## 1. 役割

```text
スマホの録音 → アプリサーバー → Whisper(STT) → LM Studio(LLM)
スマホの再生 ← 相づち／返答音声の配信 ← TTS ← 返答テキスト
                                          LLM → MCP → ESP32 → しっぽ
```

サーバーがセッションと設定の正本を持つ。スマホは音声入出力と操作・状態表示を担い、ESP32は角度制限・動作期限・手元の停止を実行する。MCPはツール接続であり、ESP32のウォッチドッグや停止機構は別途必要。

## 2. セッション・停止

| ID | 必須要件 |
| --- | --- |
| SV-01 | 開始・状態取得・終了を提供し、会話履歴と処理結果をセッションごとに分離する。セッション／発話識別子と、停止前後を識別する世代または同等の仕組みを持つ |
| SV-02 | 同一セッションの発話は1往復ずつ処理する。二重送信・二重開始を検出し、過剰な要求を無制限にキューへ貯めない。並行数・待ち行列上限と過負荷応答を決める |
| SV-03 | 停止要求はSTT・LLM・TTSの完了や会話ロックを待たず受理し、音声配信・相づち予約・新しいしっぽ動作を無効化する |
| SV-04 | 停止した世代の遅着結果を配信・実行しない。外部処理を中断できない場合も、その結果は破棄する。再接続・再起動時に古い要求を再実行しない |
| SV-05 | しっぽ停止をLLMの判断から独立した制御経路で送る。要求送信、機器の受理、停止状態の確認を区別し、未確認を停止済みと返さない |
| SV-06 | 接続監視・セッション期限・動作タイムアウトを持ち、切断時は新しい動作を許可しない。復帰後は状態確認と明示的な再開が必要 |

「おやすみ」は通常の会話終了として、短い最後の返答だけを許可してから終了する。スマホからの再生完了を確認し、音声の配信完了だけで再生完了と判断しない。失敗・通知期限切れも扱い、終了待ちを無制限に続けない。この間の新しい相づち・しっぽ開始は抑止する。手動停止・異常停止では最後の返答も取り消す。

## 3. STT・LLM・TTS

| ID | 必須要件 |
| --- | --- |
| SV-07 | 合意した音声形式だけを受信し、長さ・容量を制限してWhisperへ渡す。スマホに任意のサーバーファイルパスを指定させない。非対応形式・破損データ・無音を明示的に扱う |
| SV-08 | 空の文字起こしではLLMやしっぽ開始へ進まない。認識に失敗した発話から動作指示を推測しない。日本語での小声の認識は実機確認する |
| SV-09 | LM Studioに短く自然な日本語の返答を要求し、履歴と出力上限を持つ。思考文を読み上げない。現在の `reasoning=off` 非対応は明示的なエラーとし、無断で別モードへ切り替えない |
| SV-10 | 返答テキストをTTSへ渡し、スマホが再生できる形式で配信する。設定した声を使用し、合成失敗を成功として扱わない |
| SV-11 | STT・LLM・TTS・初回音声準備・配信・全体の所要時間を区別して測定する。各段階と会話全体に期限を設け、超過時は処理状態を終了させて通知する |

Whisper・LLM・TTSのモデル、デバイス、バージョンと設定を記録する。メモ記載のモデル名は候補で、採用・性能は実機結果で確定する。初回ダウンロードやモデルロード時間は通常の会話遅延と分け、デモ前に必要ファイルを取得して準備状態を確認する。

## 4. 相づち（MVP必須）

| ID | 必須要件 |
| --- | --- |
| SV-12 | 認識済み発話への返答待ちが設定時間を超える場合、短い相づち音声を1往復につき最大1回用意する。事前生成・キャッシュを実現方法の候補とする |
| SV-13 | 相づち／本返答にセッション・発話・停止世代を関連付け、スマホが重複・遅着・終了済み音声を除外できるようにする。実際の再生担当はスマホ1台に限定する |
| SV-14 | 本返答が先に再生可能になれば相づちを取り消す。相づち中に本返答が準備できた場合も重ならないよう再生を調停する。停止・切断で予約と配信を取り消す |
| SV-15 | 相づちと本返答に同じ声を使用し、アプリの再生音量設定をスマホに共有する。音量はスマホで1回だけ適用し、サーバーで二重に音量補正しない。同じ相づちの連続使用を避け、発話中や「おやすみ」終了処理中に追加しない |

待ち時間の起点・しきい値・音声候補・相づち中に本返答が準備できた場合の切替方法は統合前に確定する。参考実装の約0.9秒は測定条件の異なる参考値で、合否の確定値ではない。

## 5. MCP・しっぽ

| ID | 必須要件 |
| --- | --- |
| SV-16 | `tap_tail`・`stop_tail`・`get_tail_status` だけを会話用に公開する。自由なサーボ角度・任意URL・任意ツール実行は受け付けない |
| SV-17 | しっぽ開始時に、現在のセッションが動作中で、設定が有効で、明確な要求があり、停止後の古い要求ではないことを制御側で確認する。プロンプトだけを許可判定にしない |
| SV-18 | LM Studio内部で遅れてMCPが実行される場合も、MCP／機器側の許可確認で停止済みセッションの開始を拒否する。外部HTTP要求の取消だけで停止を保証しない |
| SV-19 | 期間・速さ・連続動作量を制限する。短い操作の連続要求で上限を無制限に延長しない。ESP32側にも角度・速度・時間の制限を持たせる |
| SV-20 | HTTP成功、機器の受理、実動作／停止状態を区別する。不正JSON、未知の状態、接続失敗は機械判定可能な失敗として返し、成功を示す会話に使わない |
| SV-21 | 機器用トークン、接続先と動作許可はサーバー設定で管理する。トントン設定の無効化は処理中の動作にも適用し、停止操作は開始許可が無効でも実行可能にする |

既存の0.5〜5秒・毎秒0.3〜1.0回というMCP引数制限はソフトウェア側の暫定上限で、しっぽの重さ・力・接触位置・騒音・発熱の確認済み範囲を示さない。ESP32 HTTP APIのURL・応答・認証は `app/README.md` の暫定契約をもとに担当間で確定する。

## 6. クライアントとの契約

以下は必要な論理操作であり、実装済みAPIや確定したエンドポイント名ではない。具体的なURL・HTTP／WebSocketの使い分けはこれから決める。

| 論理操作 | 入力・結果として必要な情報 |
| --- | --- |
| 準備・状態取得 | サーバー、STT、LLM、TTS、MCP、ESP32を区別した準備状態と利用可能な機能 |
| 会話開始 | 設定、セッション識別子、現在状態、受理／拒否の理由 |
| 音声送信 | セッション／発話／停止世代、音声形式・長さ・容量、受理／BUSY／拒否 |
| 音声・状態通知 | 相づち／本返答の区別、対応発話、配信順序、音声参照と有効期限、処理状態・失敗 |
| スマホからの再生結果通知 | 音声／発話／停止世代、再生開始・完了・失敗・停止。受信済みや配信済みを再生完了に置き換えない |
| 設定変更 | 要求識別子、変更値、確認された適用値・版、未反映／失敗 |
| 停止・終了 | 対象セッション、停止世代、音声停止状態、機器の停止確認または未確認 |

失敗は種類・再試行可否・対象要求を返す。切断後に同じ要求が来ても動作を二重実行しない。音声形式、サンプルレート・チャンネル数、最大長・最大容量、順序逆転時の扱いは両側で同じ値を使う。状態の受け渡しだけで機器動作を証明したことにしない。

## 7. 設定・データ・起動

- APIキーや機器トークンはサーバーの環境設定で管理し、ブラウザー、Git、ログ本文へ出さない。スマホ向けAPIは適切な認証と、マイクを使える配信構成を用意する。
- 音声アップロードの一時データは必要最小限とし、成功・失敗・停止・期限切れで削除する。履歴はセッションのメモリ内で上限を持ち、終了時に消去する。本文をログへ残す場合は明示的な設定を必要とする。
- `store=false` はLM Studioへの保存無効の要求であり、関連サービスのログ・一時データ管理も確認する。
- 起動時にモデル・実ファイルパス・LM Studio・TTS・MCP・機器の準備を確認し、利用不可の機能をスマホへ返す。再起動だけで動作を自動再開しない。
- 自作は `app/`、外部ソースは `third_party/`、モデルの配置はコード設定と実ディレクトリが一致するよう管理する。

## 10. 現行コードとの差分

| 現行部品 | あるもの | 不足するもの |
| --- | --- | --- |
| `app/voice_stt.py` | 既存ファイルのSTT、無音時の空結果 | スマホ受信、入力制限、STT全体期限、一時音声の管理 |
| `app/voice_pipeline.py` | STT→LLM、インスタンス内履歴、直列化 | TTS・配信・相づち、外部セッションAPI、優先停止、遅着破棄、待ち行列上限 |
| `app/voice_llm.py` | LM Studio呼出し、履歴／出力上限、限定MCP指定 | アプリセッションと停止許可の連携、音声完了までの全体制御 |
| `app/tail_mcp_server.py` | ツール3種、引数上限、環境設定、HTTP送信 | 現在セッションの許可確認、連続動作制限、構造化した失敗／機器確認、ESP32との実機検証 |
| Whisperの配置 | 現在のフォルダーは `ServerSide/whisper/` | コードの参照先は `ServerSide/models/whisper/`。利用する保存先を揃え、意図しない再ダウンロードを避ける |

この差分を解消するまでは「要件を文書化した段階」とし、サーバー完成・合格とは報告しない。
