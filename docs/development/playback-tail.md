# AI音声再生に連動するしっぽ

2026-10-25の利用者指定「AIが話し始める」に対応する変更。基点mainは`593103d2a97ef1f5133d7502ab031e0b4dbc4601`、作業branchは`feature/playback-tail`。稼働サービス・公開配備・機器書込みはこの変更に含めない。[MVP](../../MVP.md)が範囲とACの正本。

## 体験と開始条件

「トントンして」の合図やLLMのツール選択で動かす方式を変更し、**AI音声が端末で実際に再生され始めた時**に、準備・許可済みのしっぽをゆっくり動かす。文字生成、TTS開始、音声受信・キュー追加の時点では動かさない。

- 既存の音声`POST /api/v1/voice/sessions/{session_id}/audio-stream/playback`の`started`を利用する。新しいURL/JSONキーは追加しない。
- 相づち音声もAIの発声として含む。同一返答の相づち・本文・複数文節をまとめ、最初の実出力に対して一度だけ5000msの動作を要求する。
- 1返答につき最大5秒。長い返答でも動作を延長せず、全返答音声が先に終わった場合は途中停止する。0.3Hz固定、直近60秒の要求時間合計10000msを維持し、早期停止でも予算を返却しない。予算不足時はその返答では動かさず、後から再試行しない。
- 会話のMCP利用設定（`TAIL_MCP_ENABLED`から読み込む有効設定）と`TAIL_CONTROL_ENABLED`の両方が必要。機器のv2対応・校正・開始許可・固定個体・排他状態を各要求時にも確認し、既定無効を変えない。
- LLMや発話キーワードからのtapは開始権を持たない。モデルが動作成功を事前に語らないよう指示する。既存のstop/status経路は保持する。
- 実再生通知を持たない旧HTTPファイル/NDJSON/TCP経路では自動開始しない。PCM入力経路の旧WAV出力は実再生通知がある場合に対象となる。

## 停止・重複・遅着

- 返答生成が完了し端末の再生キューが空になった`ended`、再生`failed`、割込み、会話停止/期限/非表示/障害で、まず現在の開始許可を失効させて独立stopを送る。生成完了と再生終了を混同しない。通常の返答終了・割込みでは会話のマイク入力を継続する。
- begin_turnで作成した会話所有leaseを使う。再生開始時にleaseを作り直して、再生前の明示stopや取消を取り消すことはしない。
- `started`は一度だけ消費する。応答喪失による再送、文節追加、5秒経過後の通知、終了/失敗後の再生リトライで再開しない。古いsession/generation/turnの通知も拒否する。
- 開始taskは非同期で、音声処理や停止を機器HTTP待ちで塞がない。state/open/tapの各送信直前にも所有・実再生中・失効を確認する。通知の200を動作受付の証拠にはしない。
- 次の返答は新turnの新しい実再生でのみ新規判断する。前回の停止確認待ち/未確認、開始不明、機器再起動から自動復旧しない。機器v2のepoch/revision停止フェンスを保持し、旧APIへフォールバックしない。
- `command_stopped`は機器の指令状態。実機の停止観察とは別であり、確認不能なら`unconfirmed`を維持する。

## 繰り返し返答の配分（2026-10-25）
