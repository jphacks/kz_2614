# デモと公開前の確認

## PC音声の再現

1. [セットアップ](setup/server.md) を完了し、LM StudioとSTT/TTSのモデルを用意する。このPCの既存環境は [local-pc.md](setup/local-pc.md) を参照する。
2. ルートで `./service-local.sh start` を実行し、PC上で `http://127.0.0.1:8765/` を開く。
3. 使用するマイクを選び、会話を開始する。話している途中の文字、返答テキスト、音声出力を確認する。
4. 返答中に話しかけ、新しい発話へ切り替わることを確認する。
5. 終了操作でマイクと会話を停止する。

Web上の表示だけで物理スピーカーの聴感を確認済みとしない。モデルの初回ロードや環境によって応答時間は変わる。

## 公開製品Webの結合テスト準備

対象は [公開製品Web](https://hiroron-jphacks2026.hiroron.net/) と [ダイアリー入口（#diary）](https://hiroron-jphacks2026.hiroron.net/#diary)。2026-10-25の未ログイン確認はhiroron Passportのログイン画面までです。ログイン操作、製品UI本文、音声API到達、音声往復は今回実施していません。リポジトリの製品Webには音声API呼出しがなく、8765番の管理Webでの過去の成功を公開製品Webの合格に転記しません。

| 順序 | 確認・合格条件 | 現在の状態 |
| --- | --- | --- |
| 1. ログイン | 利用者が正規の認証を行い、製品Webへ戻れる。認証後の#diary復帰も確認 | 未ログイン時のPassport画面のみ確認。ログイン後は未確認 |
| 2. 製品UI | ホーム・#diary・月間表示・入眠準備・サウンドが切替できる。公開版のリビジョンと保存先originを確認 | ローカルUIの過去記録あり。公開UIは未確認 |
| 3. API到達 | Web担当者と既存の認証/HTTPS終端/API転送先/PCへの到達経路を確定し、製品Webから `GET /api/v1/voice/status` と `GET /api/v1/dashboard/runtime` を取得できる | 製品Webの接続実装なし。公開側の経路は未確認 |
| 4. 音声1往復 | 正しいマイクを許可し、開始→PCM送信→途中文字→返答文字→実スピーカー再生まで確認 | 公開製品Webでは未確認 |
| 5. 連続・割込み | 無音/返答再生中も入力継続。複数往復と新発話による古い返答の中断、短い通信断からの復旧を確認 | 公開製品Webでは未確認 |
| 6. 停止 | 終了操作で端末入力/出力とサーバー会話が停止し、遅着音声を再生しない。機器停止は別に検証 | 公開製品Webでは未確認 |

APIの状態応答だけではモデル接続や音声往復の合格になりません。公開HTTPSからPCのローカルHTTPへの直接接続を案内せず、[経路の確認事項](setup/hossy-web.md#公開先と音声apiの経路確認) に沿って進めます。API/音声をService Workerに保存しない条件も [製品Web仕様](requirements/web-product.md#音声統合に向けた境界) で確認します。実施時は日時・端末/ブラウザー・配信版・接続経路・各段階の結果を記録し、資格情報・音声本文は記録しません。テスト用の音声操作は稼働中入力を中断しない別の検証時間に行います。
