## 会話の開始・期限・停止

1. 利用者が毎回「会話を始める」を押す。同一originの `/api/v1/voice/status` を確認し、JSONの契約を検証する。401/403・HTML・リダイレクトを成功とせず、モデルの成功は最初の発話まで未確認と表示する。
2. 共有クライアントがマイクを準備し、16kHz mono PCMの継続送信とNDJSON/PCM出力、途中認識・返答文字を扱う。VADはサーバー側。capture-readyの時点で端末内記録の開始時刻を決める。開始前エラーだけでは成功記録を作らない。
3. 会話期限は準備完了時の15〜90分で固定する。途中の時間変更は次回会話へ反映。寝る/起きる時刻は目安だけで、開始予約/アラームはない。
4. 手動、期限、画面非表示、pagehide、音声エラー、別タブ開始で端末音声を停止する。再読込・再表示で自動再開しない。ローカル停止時点で開始/終了時刻と終了理由を記録し、サーバー停止応答の確認とは分けて表示する。停止応答未確認を停止成功と報告しない。

返答生成中も入力を継続し、新発話で旧返答を中断する共有クライアントを利用します。実マイク/実スピーカーでの製品画面往復・期限停止・非表示停止は別途受け入れが必要です。[HTTP契約](../api/voice-http.md)。

## 保存・ダイアリー

- 設定は `nengitsune-settings-v2`、記録は `nengitsune-session-v2:<id>` の別キーに保存。開始・終了・理由と予定期限（deadlineAt）を保存し、音声/会話本文を保存しない。進行中マイク状態を永続化・自動復帰しない。
- 新旧 `nengitsune-ui` / `nemuri-ui` の設定・タイマー記録は読取互換を保持。旧記録は過去のタイマーであり、マイク接続の成功として表示しない。新記録をid別に書き、古いタブが配列全体を上書きする方式を避ける。新形式の保存キーは100件まで整理し、表示は新旧を合わせて新しい開始時刻から100件まで。旧キー自体は削除しない。
- 保存/読取失敗は警告し、未保存記録は当該画面に未保存として保持する。再読込で失われる可能性を明示。storageイベントで同一originの他タブの記録/設定変更を取り込み、稼働中の会話期限は変えない。端末間同期・サーバーDB・書き出しは未実装。
- 日記は開始日のローカル日付に集計し、経過時間/回数と開始終了を表示。睡眠/寝返りは測らず「未計測」「未連携」。起動日から1/2/4/6/8/10/13日前の7日分はサンプルで、同日に実記録があれば実記録を優先する。カレンダーの●は実記録、✦はサンプル。

## PWAとAPI保護

manifestのid/start_url/scopeは `/`、表示はstandalone。モバイルは標準インストールUIまたはSafari共有メニューを案内します。保存領域はscheme/host/portとブラウザーに依存します。

SWは静的許可リストのみを対象にし、API・認証callback・音声応答を除外します。network-first、4秒の期限、通信例外/5xxではキャッシュへ戻ります。401/403・redirect・HTMLログイン画面を保存せず、無効なホーム応答では古いホームキャッシュを削除。旧SWキャッシュも更新時に除去します。音声会話はネットワーク必須です。
