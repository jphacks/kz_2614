# 製品Webアプリの仕様

更新日: 2026-10-25。HOSSy `107b762` の実装に基づきます。対象は `apps/hossy-web`。既存の音声管理画面 `apps/web` とは独立した静的Astroアプリです。

## 公開製品Webと確認範囲

製品Webの公開先は [ホーム](https://hiroron-jphacks2026.hiroron.net/)、ダイアリーは [#diary](https://hiroron-jphacks2026.hiroron.net/#diary) です。2026-10-25の未ログイン確認ではhiroron Passportのログイン画面まで確認でき、ログイン後のUI・保存・音声接続・公開版とリポジトリの一致は未確認です。以下はリポジトリ内の実装仕様であり、公開環境で受け入れ済みの機能一覧ではありません。8765番の `apps/web` はPC音声・設定管理用の別画面です。

直接表示のhashは `#diary`、`#diary-calendar`、`#routine`、`#sounds`、`#about`。画面遷移は `public/app.js` が扱います。

## 操作と状態の詳細（ソース確認）

`public/app.js`、`src/pages/index.astro`、`public/manifest.json`、`public/sw.js` を確認した仕様です。操作手順は [使い方](../web/usage.md)。公開版とソースの一致、実端末の受け入れは別途確認します。

### 遷移と表示

- ホームはhashなし、ダイアリーは `#diary`、月間は `#diary-calendar`、入眠準備は `#routine`、サウンドは `#sounds`、製品紹介は `#about`。下部ナビ、ホームのカード、ヘッダーの製品紹介ボタンから切り替えます。画面遷移はURL履歴へ追加し、日別/月間の切替は現在の履歴を置換します。
- 日別/月間タブは左右矢印キーでも切替可能。月間の日付を選ぶとその日の日別表示へ戻ります。未来の日付と未来の月への移動は無効です。
- 起動時の選択日は保存済み終了記録のうち開始時刻が最も新しい日、記録がなければ昨日です。閲覧中の日付・月・画面はlocalStorageへ保存しません。
- お知らせボタンは定型メッセージを表示するだけで、配信された通知の一覧や通知許可機能はありません。

### 入眠準備・タイマー

| 項目 | 実装上の動作 |
| --- | --- |
| 初期値 | 寝る時間22:30、話す時間30分、起きる時間07:00、サウンド「みみもとささやき」 |
| 寝る/起きる時間 | 時刻を保存・再表示する目安。開始予約、残り時間計算、起床アラームには使用しない |
| 話す時間 | 15/30/45/60/75/90分の6段階。「話す時間」という表示だが現行処理はタイマーだけ |
| 開始 | 入眠準備の「ねんぎつねとおやすみ」で現在時刻を保存し、ホームへ戻る。ホームのカードは入眠準備への入口で、直接開始/終了はしない |
| 手動終了 | 入眠準備へ戻り「おやすみ時間を終える」を押す。開始と操作時刻を記録し、進行中状態を解除 |
| 自動終了 | 1秒ごとの表示更新で期限を検知し、開始時刻+現在の設定時間を終了時刻として記録。トースト表示のみで音・通知は出ない |
| 再読込・復帰 | 保存した開始時刻と現在時刻から再計算。期限超過で起動した場合も期限時刻を記録し、閉じていた時間を別に延長しない |
| 実行中の時間変更 | 開始時刻は維持し、現在の時間設定で期限を再計算。短縮して既に期限を過ぎれば次の更新で終了する |

画面を閉じた間のJavaScript実行やOSの起床通知は保証しません。タイマーの日時は端末時計に依存し、OSのアラーム・サーバー予約・睡眠計測ではありません。

### ダイアリーの実記録とサンプル

- 終了したタイマーだけを記録し、進行中のタイマーは日記の完了件数に含みません。新規終了記録を先頭へ追加して100件まで保持し、それを超えた古い記録は取り除きます。読み込み時点で既に100件超の保存値がある場合は、次回終了処理までそのままです。
- 実記録の日付は開始日の端末ローカル日付です。日をまたいでも開始日の欄に開始/終了を1件ずつ表示し、日別合計時間・おやすみ回数を集計します。睡眠時間/寝返りの計測値ではなく、動きの記録は「未連携」、睡眠状態は「未計測」です。
- サンプルは起動日から1/2/4/6/8/10/13日前の7日分を生成し、3種類の架空の睡眠イベント・数値・グラフを使い回します。localStorageへサンプルを保存しません。同じ日に実タイマー記録があれば実記録を優先し、サンプルの睡眠グラフは表示しません。
- カレンダーの `●` は実記録、`✦` はサンプル。両者が同じ日にある場合は実記録の印を優先します。どちらもない日は「記録なし」。画面内の記録削除・修正・書き出しは未実装です。

### サウンド

「みみもとささやき」「やさしい雨音」「ふわふわの雲」「しずかな波音」の4種類から1つ選び、ホームと入眠準備に選択名を反映して保存します。試聴・再生・音量調節・音源取得は行いません。

## 保存・オフライン

- 選択、進行中タイマー、終了記録をlocalStorageの `nengitsune-ui` へ保存。旧 `nemuri-ui` を読取互換として保持する。
- 端末間の同期、サーバーDB、実機からの睡眠計測、通知配信はない。タイマーはページ復帰時に経過時刻から表示を計算し、OSのアラームを予約しない。
- Service Workerは同一originのGET応答をキャッシュし、通信失敗時に利用する。画面・静的素材のオフライン利用であり、AI会話のオフライン動作ではない。
- 配信元を変えれば保存領域は別になる。端末のサイトデータ消去・ストレージ制限による消失に備えるバックアップ機能は未実装。Safariとホーム画面版の保存領域が異なる場合もある。
- manifestのid/start_url/scopeは `/`、表示モードはstandalone。素材パスも `/` 前提で、サブパス配信へ変更する場合は全体を揃える。
- 読込時は新キーがなければ旧キーを参照し、次の保存は新キーだけへ書く。時刻形式、時間6段階、有限の開始/終了時刻を検証する。保存失敗は画面へ通知せず、その場の操作だけ続く。保存できたように見えても再起動で失われる場合がある。
- 複数タブの状態同期はない。別タブの変更を既に開いた画面へ反映せず、古い状態の保存で上書きされ得る。
- SWは起動資産とHTML内のCSSを事前取得し、同一originのGETをnetwork-firstで扱う。取得成功時に保存、通信例外時にキャッシュへ戻り、ページ遷移では必要に応じホームへ戻す。HTTPエラー応答自体にはキャッシュへ戻らない。更新時は旧nemuri/nengitsune-shellキャッシュを削除する。登録失敗は画面へ通知しない。
- ホーム追加の案内はモバイル判定時に表示する。Android等ではbeforeinstallpromptがある場合に標準インストールUIを開き、それ以外はブラウザーのメニュー手順を表示。iOSはSafari共有メニューを案内する。閉じた案内は当該ページ表示中だけ非表示で、再読込後の永続的な非表示設定ではない。

## 音声統合に向けた境界

現在のアプリにはSTT・LLM・TTS・ESP32へ接続するAPI呼出しがありません。次の `feature/web-voice-integration` では [HTTP音声仕様](../api/voice-http.md) の開始・PCM入力・NDJSON出力・割込み・停止を接続します。VADはPC側に保持します。

既存SWが全GETを対象にしているため、API接続前に `/api/` と音声応答をキャッシュ対象から除外し、古い会話や個人音声を永続化しない設計へ変更する必要があります。既存の公開側認証・HTTPS終端・API転送先とPCへの到達経路を確認し、CORS・HTTPS・配信originも合わせて検証します。公開HTTPSからPCローカルHTTPへの直接接続は前提にしません。ログインから音声往復・連続・停止までの [結合テスト表](../demo.md#公開製品webの結合テスト準備) で確認します。今回の統合ではサーバー配信先を変更しません。

## 手動受け入れ

1. 5つの画面と日別/月間の切替、直接hashアクセスを確認する。
2. 就寝・時間・起床・サウンドを変更し、同じoriginで再読込後に保持されることを確認する。
3. タイマーを開始・終了し、ダイアリーに時刻が記録されることを確認する。
4. HTTPSまたはlocalhostでPWA素材とService Worker登録、再読込・オフライン表示を確認する。
5. 実端末でホーム画面追加・再起動・保存の継続を確認する。PCのビルド成功をこの実機確認の代わりにしない。
