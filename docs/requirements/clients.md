## 1. 対象と責務

| 対象 | 現行方式 | 対応状況 |
| --- | --- | --- |
| Web | AudioWorklet入力 → HTTP PCM、NDJSON → AudioWorklet出力 | 途中STT表示、連続送受信、返答割込み、再送、設定画面を実装 |
| Android `apps/android` | AudioRecord / MediaPlayer、PCへ直接TCP | ソースあり。最新APKビルド・実機通話未確認。旧WebView APKの導入実績を流用しない |
| ESP32 `firmware/esp32/voice_tcp` | ESP-IDF通信コンポーネント | マイク・スピーカー・GPIOなし。文節PCM profile対応。ビルド・実機未確認 |
| ESP32 Reader/Follower | 可変抵抗器 → Wi-Fi → SG90 × 3 | 機器側ソース・EMORI実機記録あり。PC会話MCPとの接続は未完了 |

端末は音声入力・転送・出力・利用者操作を担当します。VAD、発話分割、STT、LLM、TTS、相づち選択、MCP呼出しはPC側です。TCP音声用ESP32部品と、サーボ用Reader/Followerは別の実装です。

## 2. 音声端末の要件

| ID | 要件と対応範囲 |
| --- | --- |
| CL-01 | 接続先・通信状態・モデル観測状態を区別する。API接続だけでモデルやサーボの正常動作を保証しない。詳細稼働表示はWeb管理画面 |
| CL-02 | ユーザー操作で開始し、マイク権限拒否・機器なし・二重開始を扱う。端末やページの再起動で自動録音しない |
| CL-03 | PCM16LE・16kHz・monoを無音も含め継続送信する。返答中も入力を受け付け、VADはPCへ委譲する。途中文字表示はWebに実装 |
| CL-04 | 相づちと本返答を順番に出力し、開始・完了・失敗を通知する。Webは100ms以下のPCMフレーム、現Android/ESP32部品は文節単位。新profile対応は別作業 |
| CL-05 | 手動停止でローカル入力・出力を直ちに止め、LLM完了を待たずPCのセッションを停止する。サーボ停止の接続は未実装で、機器停止済みと表示しない |
| CL-06 | 古いsession/generationの音声を捨てる。Webはinterruptionで旧turn音声も破棄し入力を維持。Android/ESP32の同等の割込み対応・実機確認は未完了 |
| CL-07 | Webで入力音量・サーバーTTS出力音量・設定を変更する。入力倍率と端末の物理音量を区別。希望頻度の保存を実機反映と表示しない |
| CL-08 | 接続・入力・認識・生成・出力・停止・失敗を表示する。返答の生成完了と端末出力完了を区別する |
| CL-09 | Webは番号確認と有界再送で短い遅延から復旧し、長い切断は手動再開。TCPは通信断で停止し、新規接続から手動再開する。Webの復旧方式をTCPにも実装済みとしない |
| CL-10 | Webは入力機器選択と25〜200%入力音量、60/100/150%プリセットを提供。HyperX指定時に内蔵へ無断で切り替えない。倍率はPCMごとにPCへ送りサーバーで適用する |

## 3. Webの入力と出力

会話開始後の追加録音ボタンは不要です。AudioWorkletがPCMを4096 samples（256ms/8192 bytes）ごとに送ります。入力・状態取得・返答受信・出力通知を並行し、途中STTが確定認識で修正されても古い結果へ戻さないようにします。

Webは `pcm_s16le_16000_stream` を要求し、最大100msの `audio_frame` を受けて出力します。親cursorとframe_indexで再送の重複を除きます。生成完了の `complete` だけで出力完了とせず、出力キューが空になってから `ended` を通知します。

短い通信遅延中は未確認分込み最大960,000 bytesを保持し、同じ音声・連番・倍率を再送します。1パケットの復旧予算は24,750msです。上限や重大障害を超えたら理由を表示して終了します。通信仕様の詳細は [HTTP API](../api/voice-http.md) を参照してください。

## 4. 割込み・停止・相づち

- 新しい発話をPCのVADが検知したら、Webは古い返答と待機音声を破棄します。マイク入力を止める操作ではありません。
- 手動停止・画面離脱・入力機器切断では端末音声を停止し、PC会話の終了を要求します。復帰後は手動で開始します。
- 相づちはサーバーが候補・タイミングを決定し、1ターン最大1回。本返答と音声を重ねません。
- 「おやすみ」は短い返事と相づち抑止の対象ですが、最後の出力後に自動終了する制御は未完了です。音声管理画面の手動停止に加え、PR #25の製品Webには開始時に確定した期限による停止があります。
- 将来のサーボ停止では、要求送信・機器受理・状態確認を区別する表示が必要です。現在の音声停止にその確認機能はありません。

## 5. 接続とプラットフォーム別制約

| 対象 | 接続・形式 | 残る確認 |
| --- | --- | --- |
| Web | localhostはHTTP、別端末のマイクはHTTPS等のsecure contextが必要 | HyperX、出力の回り込み、スマホHTTPSと音声権限 |
| Android | TCP v1、profile省略で `original`、MediaPlayer用の文節キャッシュ | 最新APK、録音/再生、interruption対応、画面ロック・Wi-Fi切断 |
| ESP32音声 | TCP v1、`pcm_s16le_16000`、PCM文節最大512KiB | ESP-IDFビルド、音声IO組込み、メモリ容量、割込み、新stream profile |

TCPサーバーは `pcm_s16le_16000_stream` も提供しますが、サーバー対応だけでAndroid/ESP32が対応したとは扱いません。[TCP契約](../api/voice-tcp.md) / [ESP32通信部品](../../firmware/esp32/voice_tcp/README.md)。

Web管理画面のVAD・モデル設定は保存して新会話へ反映します。Androidネイティブアプリは音声通話専用で、Web管理画面の設定・参照WAV選択を実装済みとしません。

通常音声は保存しません。AndroidはMediaPlayerのためアプリ専用キャッシュへ文節ファイルを置き、出力完了・失敗・停止・次回起動で掃除します。強制終了直後には残存する可能性があります。ESP32通信部品では受信イベントとPCMの所有権を明確にして解放します。

## 6. ESP32しっぽとの境界

現行MCPはPC内の希望頻度の保存・取得だけです。Followerの実動作仕様は [ESP32資料](../esp32/README.md) を参照します。端末からMCPや機器の自由角度APIを直接呼び出す設計にしません。

PC設定の0.3〜1.0Hzと実機引き継ぎの0.3回/秒固定を混同しないでください。現在のFollowerはtap終了・stop後に最終指令位置を保持し、自動でReaderへ戻りません。中立解除でReader追従が再開し得るため、PC側が自動解除する仕様にはしません。

## 製品Web/PWAとの区別

`apps/hossy-web`はホーム・ダイアリー等の製品UIに、`apps/web`の共有音声クライアントを接続するMVPです。同一originのAPI転送設定が必要で、実マイク・公開環境は未検証です。管理者共通の設定APIを個人UIへ接続せず、本人/人形所有権や実機モードは未実装です。[製品Web仕様](web-product.md)を参照してください。
