## 1. 製品と対象範囲

利用者の音声をPCで認識し、短い日本語の返答を生成して端末へ音声を返す、きつね型の添い寝ロボットです。しっぽはESP32とSG90 3台で制御します。音声会話と機器の両方に実装がありますが、会話からサーボを動かす接続は未完了です。

| 領域 | 役割 | 主な配置 | 担当 |
| --- | --- | --- | --- |
| 製品Web/PWA | ホーム・ダイアリー・音声会話接続・端末内時刻/理由保存。実音声未検証 | `apps/hossy-web` | HOSSy |
| 音声・設定Web | 設定、マイク入力、途中文字表示、返答音声出力 | `apps/web` | HOSSy |
| Android | ネイティブ音声通話、TCP送受信 | `apps/android` | 担当者名未指定 |
| PC | HTTP/TCP受付、設定・会話状態、VAD、STT、LLM、TTS、MCP仲介 | `server/api`・`server/ai` | kameyama |
| しっぽ機器 | Readerの可変抵抗入力、FollowerのHTTP受付・3台のPWM | `firmware/esp32` | EMORI |
| ESP32音声部品 | TCP通信。機器のマイク・スピーカーIOは別途組込み | `firmware/esp32/voice_tcp` | AI・機器担当の共同 |

## 2. 利用者から見た動作

| 場面 | 仕様 | 現状 |
| --- | --- | --- |
| 製品Webの会話期限 | 時間・サウンドを選び、音声準備完了/端末停止の時刻と理由を記録 | 共有音声接続実装。アラームなし、実音声未検証 |
| 会話開始 | 利用者の操作でマイク入力を始める。追加の録音ボタンは不要 | Webに実装 |
| 話している間 | 無音も含めてPCMを送り、PCのVAD/STTで途中文字を更新 | Web・PCに実装 |
| 返答待ち | 認識した本文と会話履歴をLLMへ渡す。必要なら短い相づちを最大1回 | PCに実装 |
| 返答中 | 文節が合成できた順に音声を転送する。入力は継続 | Web・PCに実装 |
| 話しかけ直し | 新しい発話で古い返答だけを中断する | Web・PCに実装。Android/ESP32端末対応は残る |
| 手動停止 | 端末の入力/出力とPC会話を終了し、古い結果を破棄する | 音声経路に実装。サーボ停止の統合は未実装 |
| 頻度の変更 | PCに希望値を保存し、保存結果として返す | 会話MCPに実装。実機反映を保証しない |
| 会話からトントン | 明示要求・許可・現在の会話を検証して機器を動かす | 今後の統合対象 |
| おやすみ | 短く応答し相づちを抑止する | 最後の音声後の自動終了は未完了 |

音声入力・認識・生成・出力の流れと、割込み・通信復旧のMermaid図は [構成と処理フロー](../architecture.md) に集約しています。ESP32の入力ループとモード遷移は [機器仕様](esp32.md) を参照します。

## 3. 通信の境界

| 接続 | 現行の契約 | 正本 |
| --- | --- | --- |
| 製品Web ↔ 端末内 | localStorageと静的SW。同一origin経由で音声APIへ接続 | [製品Web仕様](web-product.md) |
| 音声・設定Web ↔ PC | HTTP継続PCM、独立したNDJSON出力、状態照会、出力結果通知 | [HTTP音声API](../api/voice-http.md) |
| Android / ESP32音声 ↔ PC | TCP v1。4-byte長+JSON、1接続1会話 | [TCP音声API](../api/voice-tcp.md) |
| PCアプリ ↔ LLM | LM Studio。MCP有効時は互換Chat API、無効時はnative Chat API | [サーバー要件](server.md) |
| PCアプリ ↔ MCP ↔ PC設定 | stdio、頻度2操作、保存成功のみ | [PC頻度API](../api/tail-frequency.md) |
| Reader / 手動操作 ↔ Follower | HTTP :80。角度・往復・モード・有限タップ | [機器HTTP API](../api/esp32-http.md) |
| PC会話 ↔ MCP ↔ Follower | 実機3操作へ接続する設計。現時点では未接続 | [MCP統合仕様](../esp32/mcp-integration.md) |

Webは16kHz・mono・PCM16LEを継続送信し、完成したTTS文節を最大100msのPCMフレームで受信します。TTSモデル内部の計算途中からサンプルを取り出す方式ではありません。サーバーの新出力profile対応とAndroid/ESP32の端末対応は別です。

音声の連番・停止世代・再送上限は音声APIに定義します。Followerの機器APIはsession_idや停止世代を受け付けません。音声APIの識別子をそのまま機器へ追加する実装にしないでください。

## 4. しっぽの3つの状態を混同しない

| 区分 | 何を意味するか | 確認できないこと |
| --- | --- | --- |
| PCの希望頻度 | 0.3〜1.0Hzを保存した設定。`device_confirmed=false` | 機器への送信・反映・実動作 |
| Followerの指令状態 | 有限タップ・保持・モード。`feedback=command_only` | 機械の実角度、接触、実際の停止 |
| 操作者の実機確認 | 対象機構・日時・条件の下での観察や測定 | 別の個体・設定・ネットワークでも同じ結果になること |

既存機構の記録はタップ上限0.3回/秒。実機MCP提案も0.3固定です。PCに保存できる上限1.0Hzを実機へそのまま適用しません。有限動作は0.5〜5秒、受理時間の予算は60秒の窓で合計10秒までです。片側の端への到達を1回とし、1往復の回数とは区別します。

`tail/stop`は最終指令を保持、`neutral`は中立へ移動、`relax`はPWM停止です。いずれも物理的な電源遮断と同義ではありません。詳細な許可条件、エラー、モード、校正値は [ESP32機器仕様](esp32.md) と [機器HTTP API](../api/esp32-http.md) を正本とします。

## 5. 共通の運用・データ要件

- VAD、発話分割、入力倍率の適用はPC側。Web/ESP32へ独自のVADを追加しません。
- 入力と返答出力は並行します。処理中に新発話を拒否する方式には戻しません。長い通信断は有界の保存・再送後に失敗を知らせます。
- 停止はLLM完了を待ちません。終了した会話/発話の結果は破棄します。実行中のネイティブ推論が残る場合も結果を再配信しません。
- 通常の会話音声と本文は保存・ログ出力しません。明示登録の参照WAVと明示生成の相づち素材は保存対象の例外です。
- `.env`、実Wi-Fi設定、モデル、参照/生成音声、端末校正の個別情報は配布用ソースと区別します。[Git除外方針](../development/gitignore.md) に従います。
- コード上の既定値、保存設定、稼働中の観測値、過去の実測値を分けます。過去のIP/COM番号を現在値として扱いません。
