## 1. 対象と実装状況

PCサーバーが入力音量、Silero VAD、Whisper、LM Studio、Irodori-TTS、相づち、会話履歴、停止世代を管理します。WebはHTTPで継続PCMを送受信します。AndroidはネイティブTCPアプリへ移行済みのコード、ESP32音声はTCP通信部品を持ちます。端末にVADを置きません。

| 対象 | 現行実装 | 検証の境界 |
| --- | --- | --- |
| Web音声 | 継続PCM、途中STT、文節TTS転送、割込み、再送 | PC実モデルHTTPの確認記録あり。最新方式のHyperX・物理出力聴感は残る |
| TCP音声 | 独立プロセス、長さ付きJSON、音声profile、再生通知 | 模擬モデルでの実ソケット試験あり。TCP実モデル・端末通話は未確認 |
| MCP頻度 | アプリ所有stdioで希望値の保存・取得 | 自動テストと実モデルの記録あり。機器反映の確認はしない |
| ESP32実制御 | Reader/Followerと提案MCPを資料として統合 | 会話bridgeとの接続・独立停止・停止後の遅着開始拒否は未実装 |

以下のIDは従来要件との対応を維持します。「実機接続時の要件」は、現行コードが満たしているという意味ではありません。

## 2. セッション・停止

| ID | 現行要件と状態 |
| --- | --- |
| SV-01 | 会話をsession_id、turn_id、generationで分離し、最大4セッション・無操作15分期限を持つ。実装済み |
| SV-02 | 入力は生成・出力中も受け付ける。PCMは連番で重複を除き、新発話で旧返答を取消する。旧ファイル送信は同一会話の並行ターンを拒否する。無制限キューは作らない |
| SV-03 | 手動停止はLLM完了を待たずセッションを停止し、相づち・音声配信を無効化する。ESP32への独立停止は今後の実機接続時に必要 |
| SV-04 | 停止世代・発話IDで遅着結果を捨てる。実行中のネイティブ推論は強制中断できない場合があり、終了後に結果破棄・後片付けする |
| SV-05 | 実機接続時はLLMを介さずしっぽ停止を要求し、送信・受理・停止状態確認を区別する。現行は未接続で、音声セッション停止をサーボ停止済みと報告しない |
| SV-06 | Webは有界の再送で短い切断から復旧し、上限超過・致命的エラーは手動再開。TCPは切断でセッションを破棄し、自動復元しない |

話しかけ直しではセッションとPCM連番を維持し、旧返答のみを無効化します。手動停止は入力と出力を終了します。「おやすみ」の短い応答指示と相づち抑止はありますが、最後の音声出力完了を待って自動終了する制御は未完了です。

## 3. STT・LLM・TTS

| ID | 要件 |
| --- | --- |
| SV-07 | PCMは16kHz・mono・s16le、1〜32,000 bytesの偶数長。旧ファイル入力は対応コンテナを検査し25MB・60秒まで。任意ファイルパスを受け付けない |
| SV-08 | 無音・空本文はLLMや動作開始へ進めない。途中STTは参考表示で、確定STTで修正できる。小声・騒音環境は実機評価する |
| SV-09 | 今回の認識本文と過去の履歴を分離してLLMへ渡す。音響特徴は参考情報に限定する。思考文を読み上げず、reasoning出力はエラーとする |
| SV-10 | 既存の文節分割でTTSを生成し、完成した文節から順次転送する。Webは最大100msのPCMフレームで出力する。モデル内部の生成途中サンプルを転送する仕様ではない |
| SV-11 | 段階時間と全体時間を区別する。STT/TTS既定90秒、LLM既定45秒、ターン全体180秒。期限切れ後は旧結果を配信しない |

### 既定値とこのPCの確認記録

| 段階 | コード・設定例の既定 | このPCの確認記録 |
| --- | --- | --- |
| STT | Whisper small、日本語、CUDA/float16 | small、CUDA/int8_float16で確認した記録あり |
| LLM | `google/gemma-4-26b-a4b-qat`、出力160token、context4096、履歴8メッセージ、45秒 | LM StudioとのHTTP往復記録あり |
| TTS | 設定例はGradio・v3 VoiceDesignも保持。local backendへ切替可能 | local Irodori v4.1 Small、CUDA/bf16、codec CUDA/fp32での記録あり |

現在の有効設定は保存済みダッシュボード設定・環境変数、実行状態はruntime APIで確認します。設定例のモデルやGPU指定を稼働済みと扱いません。[設定例](../../server/.env.example) / [実測記録](../setup/local-pc.md)。

MCP無効時はLM Studio native `/api/v1/chat`（`input`、`reasoning=off`）、有効時は互換 `/v1/chat/completions`（`messages`、`reasoning_effort=none`）を使います。両経路で保存を抑止する要求を送りますが、外部サービスの保存方針まで保証するものではありません。認識本文・返答本文をアプリログに残しません。

VADの開始/終了しきい値、最小発話、終端無音、先頭保持、最大発話長を検証して保存します。新会話開始時に固定し、設定保存で進行中の入力を止めません。Whisper内VADは別の設定です。

## 4. 相づち

| ID | 要件と実装 |
| --- | --- |
| SV-12 | 候補・準備・待ち時間の判定をサーバーで行う。参照音声等が一致する保存素材を優先し、なければTTSでメモリに準備する |
| SV-13 | 相づちを会話・発話・世代に紐付ける。端末は音声出力と結果通知を担当する |
| SV-14 | 本返答が先に用意できたら省略。待ち時間を超えた場合も最大1回。音声を重ねず順番に出力し、割込み・停止で旧音声を捨てる |
| SV-15 | 同一声・設定の候補を循環し、発話中や終了要求で追加しない。サーバー出力音量0〜200%は相づちにも適用する。端末の物理音量とは別 |

候補は「うんうん」「ふーん」「へー」、既定待ち時間は0.9秒。準備は逐次返答経路から行います。Web PCMには出力開始・完了・失敗通知があります。旧ファイル送信NDJSONの通知連携は未実装です。

## 5. MCP・しっぽ

現在の会話ツールは頻度2種だけです。実機MCPの3操作への移行は最新の要求ですが、まだ実装されていません。[頻度API](../api/tail-frequency.md) と [ESP32統合課題](../esp32/integration-review.md) を区別します。

| ID | 現行要件 / 次の実機接続で満たす条件 |
| --- | --- |
| SV-16 | 現行allowlistは `set_tail_frequency`・`get_tail_frequency`。実機移行では `tap_tail`・`stop_tail`・`get_tail_status` に限定する。自由角度・任意URL・任意ツールは公開しない |
| SV-17 | 実機開始は明示的な現在の要求、動作許可、活動中セッション、停止世代を制御側で検証する。プロンプトだけで許可しない。未実装 |
| SV-18 | 停止後に遅れて届く開始を拒否する。MCP内の実行中要求だけの世代検査では不足。呼出し経路との統合が必要。未実装 |
| SV-19 | 引き継ぎの実機は0.3回/秒固定、0.5〜5秒、60秒枠で受理時間合計10秒まで。重複開始・開始の自動再送で延長しない。PC設定値0.3〜1.0Hzとは別契約 |
| SV-20 | HTTP成功、指令状態、物理フィードバックを区別する。現行頻度結果は常に `device_confirmed:false`。Followerの `command_only` は実測位置ではない |
| SV-21 | 機器URL・許可はPCで管理。実機停止は開始許可が無効でも送れるようにする。中立/脱力の解除やReader追従復帰を自動化しない |
| SV-22 | LLMの要求をPCアプリが検証してstdio MCPへ渡す。端末から機器APIへ直接接続しない。実機接続時もこの許可境界を維持する |

現MCP bridgeは子プロセスへ `TAIL_CONTROL_ENABLED=false` を渡します。提案Pythonの丸ごと置換や `.env` の変更だけでは新しい3操作は接続できません。Followerのtap JSONは `duration_ms` と `rate_hz` の2項目のみで、対応していないsession/generationを追加してはいけません。

## 6. クライアントとの契約

| 経路 | 契約 | 主な動作 |
| --- | --- | --- |
| Web HTTP | [VOICE_API.md](../api/voice-http.md) | session作成、PCM POST、状態GET、NDJSON events、playback通知、DELETE停止 |
| 旧ファイル入力 | 同上 | WebM/Ogg/WAV/MP4、25MB・60秒、逐次応答または期限付き音声URL |
| Android/ESP32 TCP | [VOICE_TCP.md](../api/voice-tcp.md) | 4-byte長+JSON、1接続1session、PCMと結果の並行送受信 |
| 頻度保存 | [TAIL_FREQUENCY_API.md](../api/tail-frequency.md) | PC内設定のGET/PUT。ESP32の受理を示さない |
| 設定・参照WAV | [dashboard README](../../server/api/README.md) | 検証付き保存・取得・削除、任意パスを受け付けない |

Webは送信中も状態GETを続け、同session/generationの受理番号でPOST応答の欠落から回復します。1パケット8秒/試行・復旧予算24,750ms、入力保持960,000 bytes。音声・倍率・連番を変えず再送し、上限超過を無音の破棄で隠しません。VAD重大障害では同じPCMを再処理せず終了します。

## 7. 設定・データ・起動

- 保存済み設定は同項目の環境既定より優先し、新会話へ反映。入力音量25〜200%は会話中もPCMごとに適用します。
- runtime APIは次回設定と観測値を分け、状態取得だけではモデルをロード・推論・リセットしません。
- 音声・会話履歴はメモリと処理用一時ファイルに限定。旧返答URLは2分保持、停止・期限切れで破棄します。明示登録の参照WAV、明示生成の相づち素材は固定先へ保存します。
- `.env`、`server/api/data/`、モデル、外部ランタイム、音声、ビルド成果物はGit除外。[除外方針](../development/gitignore.md) を参照してください。
- 開発時は認証なし。HTTPは既定loopback、LANブラウザーのマイクにはHTTPSが必要。ネイティブTCPにはブラウザーのHTTPS要件は適用されませんが、通信自体は暗号化されません。インターネット公開は対象外です。
- HTTPとTCPを別々に起動するとGPUモデルが重複する可能性があります。文書更新や状態確認のために追加モデルをロードしたり、音声入力を中断したりしません。
