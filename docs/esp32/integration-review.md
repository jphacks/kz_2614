## 理解した契約

対象はRaspberry PiではなくESP32 FollowerとSG90×3。公開操作はtap_tail(duration_seconds=5.0)、stop_tail()、get_tail_status()の3つ。開始時間0.5〜5秒、速度0.3固定。tapはPOST /api/tail/tapへduration_msとrate_hzだけを送る。停止はPOST /api/tail/stop、状態はGET /api/tail/statusとGET /api/status。認証は追加しない。

開始後・停止後は最後の指令角で保持する。停止は90度中立移動や脱力ではない。中立・脱力の自動解除はしない。起動しただけでは機器へ指令を送らない。ESP32の60秒当たり10秒の予算制限では自動再試行しない。command_onlyは物理位置や接触を確認した結果ではない。

## このPCとの重要な差分

1. 現在の会話はLM Studio互換APIとアプリ所有stdio MCPを使用する。メモのLM Studio native MCP登録だけでは今の呼出し元へ接続されない。既存の認証なし経路を維持して3操作へ接続する必要がある。
2. llm/tail_tools.pyのallowlist・引数・結果検証・会話説明は現在set_tail_frequency/get_tail_frequency専用。MCP本体だけを提案版へ置換するとツール検出が失敗し、会話経路を壊し得る。
3. 同ファイルのMCP起動環境はTAIL_CONTROL_ENABLED=falseを明示指定している。.envだけtrueへ変更してもこの環境値が優先される。
4. 会話停止ボタンからの独立した機器停止と、開始前のセッション/停止世代照合が必要。MCPプロセス内だけの停止世代では、未到着の古いLLM要求は拒否できない。
5. ESP32へsession_id/command_id/stop_generationを送る変更では解決できない。現行機器のJSONは2項目のみ。
