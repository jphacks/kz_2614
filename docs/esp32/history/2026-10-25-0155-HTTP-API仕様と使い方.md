# ESP32 Follower HTTP API 仕様と使い方

作成日時: **2026-10-25 01:55 JST**。`ESP32-Follower/ESP32-Follower.ino`と`ESP32-Reader/ESP32-Reader.ino`の現行ソースを確認して記載。IPアドレスと実機試験結果は2026-10-24の記録に基づき、この文書の作成時にネットワークへ再接続して確認したものではない。

## 接続先と共通ルール

- APIサーバーは**受信側ESP32（Follower）**のHTTPポート80で動作する。ReaderはクライアントとしてFollowerへ角度を送る。
- APIを操作するPC・スマートフォン等は、Followerと通信できる同じLANに接続する。ESP32が使うWi-Fiは2.4 GHz帯。
- 受信側IPの前回の確認値は`192.168.100.111`。DHCPで変わる可能性がある。Followerのシリアルモニタを115200 bpsで開き、`Servo ESP32 IP:`の表示で現在値を調べる。
- mDNSが使える環境では`http://esp32-servo.local`も利用できる。名前解決できない場合はIPを使用する。
- POSTの入力は`application/x-www-form-urlencoded`形式。パラメータ名・モード値は小文字で指定する。成功時はHTTP 200、`application/json; charset=utf-8`のJSONを返す。エラー時はテキストを返す。
- 認証およびHTTPSは実装していない。同じLANの端末から操作できるため、インターネットへ直接公開しない。

## エンドポイント

| メソッド | パス | 入力 | 動作 |
| --- | --- | --- | --- |
| GET | `/api/status` | なし | 現在のモード・指令値・PWM設定を取得 |
| POST | `/api/angle` | `angle=0..180` | 先端の指定角度へ動かして保持し、`api`モードになる |
| POST | `/api/konkon` | `start_angle=0..180`、`end_angle=0..180`、`speed=1..180` | 指定した2角度の間を往復する |
| POST | `/api/mode` | `mode=teleop`、`mode=neutral`、`mode=relax` | 動作モードを切り替える |
| POST | `/api/teleop` | `angle=0..180` | Readerが可変抵抗器の角度を送る |

角度パラメータは**数字だけの整数**で、0～180。負数、小数、空文字、範囲外の値は受け付けない。0°側で3台のリンクが丸まり、180°側で伸びる構成。各SG90には共通のパルス幅を出し、先端の指令範囲を各関節へおよそ3分の1ずつ分配する。角度と速度は**指令値**であり、軸や先端の実測値ではない。

### `POST /api/angle`

例: `angle=90`。指定角度の指令を出し続ける。`konkon`実行中に呼ぶと往復を止め、その角度で保持する。移動速度は指定できず、サーボの応答に依存する。API操作中はReaderの`/api/teleop`をHTTP 409で拒否する。Readerに戻すには`mode=teleop`を送る。

### `POST /api/konkon`

例: `start_angle=0&end_angle=180&speed=60`。開始角度と終了角度は異なる整数で指定する。現在の指令角度から開始角度へ向かい、その後2角度間を停止するまで往復する。`speed`は先端の**指令角度の変化速度（度/秒）**で、許容範囲は1～180。制御の更新間隔は約20 ms。回数・継続時間を指定する機能はない。実機では0～180°、60°/秒の動きの幅と速さが良好と確認されたが、機械的な速度は測定していない。

停止方法: `/api/angle`で任意の角度を保持するか、`mode=neutral`で中立へ戻すか、`mode=relax`でPWMを止めるか、`mode=teleop`で可変抵抗器操作に戻す。Wi-Fiが切断されたときは往復を止め、最後の角度指令を保持する。

### `POST /api/mode`

| `mode` | 動作 |
| --- | --- |
| `teleop` | Readerからの角度指令を再び受け付ける。脱力からの復帰時は先に3台へ1500 µsを出し、その後Readerのつまみ位置へ追従する |
| `neutral` | 3台すべてに1500 µsを出して中立位置で保持する。Readerと角度・往復APIからの指令は拒否する |
| `relax` | 3台のGPIO18・19・21のPWMデューティを0にしてパルスを止める。往復も停止する。**サーボの電源は切れない** |

脱力中は`/api/angle`、`/api/konkon`、Readerの`/api/teleop`をHTTP 409で拒否する。脱力時はリンクが自重で動く可能性があり、復帰時は中立またはつまみ位置へ動く。リンクを支えられる状態で操作する。完全な電源遮断には別途電源スイッチ回路が必要。脱力モードは再起動後に保持されず、起動時に中立を出してから通常のテレオペに戻る。

### `POST /api/teleop`

送信側Readerが自動で`angle`を送るためのAPI。`teleop`モード中に受け付ける。`api`・`konkon`モード中はReaderの指令がHTTP 409となり、APIからの操作を上書きしない。通常は手動で呼ぶ必要はない。

## PowerShellでの操作例

Windows PowerShellでは`curl.exe`を使う。`-i`はHTTPステータスを表示する。実際の受信側IPに合わせて`$base`を書き換える。`-d`を使用するとPOST本文がフォーム形式で送信される。

```powershell
$base = "http://192.168.100.111"

curl.exe -i "$base/api/status"
curl.exe -i -X POST -d "angle=90" "$base/api/angle"
curl.exe -i -X POST -d "start_angle=0&end_angle=180&speed=60" "$base/api/konkon"
curl.exe -i -X POST -d "angle=75" "$base/api/angle"
curl.exe -i -X POST -d "mode=relax" "$base/api/mode"
curl.exe -i -X POST -d "mode=neutral" "$base/api/mode"
curl.exe -i -X POST -d "mode=teleop" "$base/api/mode"
```

最初の動作試験でリンクの周囲に余裕が必要な場合は、狭い範囲・低速の`start_angle=60&end_angle=90&speed=15`を使用する。前回の実機試験では0～180°、60°/秒も異常なしと報告された。

Postmanではメソッドを`POST`、URLを各APIのURLにし、**Body → x-www-form-urlencoded**でキーと値を入力する。例えば`/api/angle`ならキー`angle`、値`90`。ブラウザのアドレス欄から送れるのはGETリクエストなので、POSTには`curl.exe`やPostmanなどを使う。サーバーにはCORSヘッダーの設定がないため、別オリジンのWebページから直接`fetch`する構成ではブラウザ側の制約にも注意する。

## ステータス応答

`GET /api/status`および成功したPOSTは状態をJSONで返す。以下は中立モード、前回保存した校正値に基づく例。

```json
{
  "angle": 90,
  "mode": "neutral",
  "pwm_enabled": true,
  "pulse_us": 1500,
  "joint_angle_deg": 90.0,
  "curl_extra_us": 100,
  "pulse_min_us": 600,
  "pulse_max_us": 2400,
  "neutral_pulse_us": 1500,
  "joint_count": 3,
  "konkon_start_angle": null,
  "konkon_end_angle": null,
  "konkon_speed_dps": null,
  "konkon_target": null,
  "servo_pins": [18, 19, 21]
}
```

| フィールド | 意味 |
| --- | --- |
| `angle` | 先端の最後の指令角度。脱力中も最後の値を表示し、実測位置は示さない |
| `mode` | `teleop`、`api`、`konkon`、`neutral`、`relax`のいずれか |
| `pwm_enabled` | ソフトウェア上のPWM出力状態。実機の回転や電源電流の測定値ではない |
| `pulse_us` | 3台へ共通で指令するパルス幅。脱力中は`null` |
| `joint_angle_deg` | パルス幅と校正範囲から計算した各関節の名目角。脱力中は`null` |
| `curl_extra_us` | 0°側を追加で丸める調整量 |
| `pulse_min_us`、`pulse_max_us` | 保存された校正範囲。常にその両端を3台へ指令する意味ではない |
| `neutral_pulse_us` | 中立指令のパルス幅（1500 µs） |
| `joint_count` | 関節数（3） |
| `servo_pins` | 信号線のGPIO番号（18、19、21） |
| `konkon_start_angle`、`konkon_end_angle`、`konkon_speed_dps`、`konkon_target` | 往復中の設定と現在目指している端の角度。往復停止中は`null` |

## HTTPエラー

| コード | 意味 |
| --- | --- |
| `200` | 成功。JSONを返す |
| `400` | 必須パラメータ不足、角度・速度の不正、未知の`mode`など |
| `409` | 中立・脱力中の角度／往復指令、またはAPI操作中のテレオペ指令 |
| `503` | サーボPWMを利用できない |
| `404` | 存在しないパス |

HTTP応答そのものがない場合は、IP、Wi-Fi接続、同じLAN内で通信できるか、Followerの電源とシリアル出力を確認する。

## 2026-10-25追記: LLMしっぽMCP専用API

現行のMCPが呼ぶ`POST /api/tail/tap`、`POST /api/tail/stop`、`GET /api/tail/status`をFollowerへ追加した。ユーザー指定によりプロトタイプはトークン認証なしで接続し、Authorizationヘッダーも不要。`tap`の本文はJSONで、`duration_ms`が500～5000。プロトコル上の`rate_hz`は0.3～1.0だが、現在の実機設定は上限0.3なので**0.3だけ受理**する。0°～180°の指令幅で、期限になると最後の角度で停止する。`stop`は動作許可設定に関係なく停止し、`status`の`feedback:"command_only"`は物理位置を測っていない意味。詳細とLLM側への引き継ぎは[LLMしっぽMCP統合調査](2026-10-25-0222-LLMしっぽMCP統合調査.md)を参照。

最初の5秒試験で固定部の揺れが見えたため一度PWMを止めた。後の再試験ではユーザーが5秒の動作と途中停止・90°中立への復帰を実機で確認し、異音・接触・引っ掛かりなしと回答した。FollowerのMCP APIはローカル設定で有効、現在は90°中立。LLM側サーバーの自動タップは、明示要求の判定・停止後の古い開始要求の拒否・独立した停止経路が未実装なので無効のままにする。
