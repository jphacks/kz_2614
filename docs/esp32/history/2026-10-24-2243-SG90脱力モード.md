# SG90 3台の脱力モード

## 変更

- Followerの`POST /api/mode`へ`mode=relax`を追加。GPIO18・19・21のLEDCデューティを0にして3台への50 Hz指令パルスを止める。サーボの別電源は切らない。
- 脱力開始時に`konkon`を停止し、脱力中の`/api/angle`、`/api/konkon`、Readerからの`/api/teleop`をHTTP 409で拒否する。
- `GET /api/status`へ`mode=relax`、`pwm_enabled=false`を追加。脱力中の`pulse_us`と`joint_angle_deg`は`null`。`angle`は最後の指令値で、実際の軸角ではない。
- `mode=neutral`は3台へ1500 µsを出して中立に戻す。`mode=teleop`は脱力から復帰するとき、まず1500 µsを出し、その後Reader指令へ追従する。シリアルの`d`で脱力、`n`で中立、`t`でテレオペへ切り替えられる。再起動後は従来どおりテレオペになる。

## 操作例

ESP32と同じWi-Fiにいる端末で、実際のFollower IPへ送る。以下の`192.168.100.111`は今回の確認時の値。

```powershell
curl.exe -X POST -d "mode=relax" http://192.168.100.111/api/mode
curl.exe http://192.168.100.111/api/status
curl.exe -X POST -d "mode=neutral" http://192.168.100.111/api/mode
curl.exe -X POST -d "mode=teleop" http://192.168.100.111/api/mode
```

脱力でリンクが自重で動く可能性があるため、支えられる状態で操作する。再開時は中立またはつまみ位置へ動く。完全に通電を切る用途には別の電源スイッチ回路が必要。

## 実機確認（2026-10-24）

- Follower（MAC `70:4b:ca:82:40:18`、COM11）でビルドと書き込み・フラッシュ照合が成功。高速転送で一度シリアルが途切れたが、115200 bpsで再書き込みし照合に成功した。
- 停止前はGPIO18・19・21で約1100 µsのHIGHパルス。シリアル`d`後は3ピンのHIGH検出がすべてタイムアウトし、LEDCデューティも0。ユーザーの観察で保持力が弱まった。
- 同じWi-Fi上のReaderへ一時試験プログラムを入れ、`GET /api/status`はHTTP 200で`mode=relax`・`pwm_enabled=false`・`pulse_us=null`。脱力中の`POST /api/angle`はHTTP 409。`mode=neutral`・`mode=relax`・`mode=teleop`はHTTP 200。復帰後は3ピンとも約1502 µsを出した。
- Reader（MAC `70:4b:ca:4e:02:60`、COM6）に元の可変抵抗器用スケッチを戻してフラッシュ照合。FollowerはReaderの0°指令を受け、3ピンとも約1101 µsを出した。
- PCからのHTTP直接アクセスとサーボ停止時の消費電流は未測定。パルス測定はESP32のGPIOパッド入力で行ったもので、サーボ端子での波形測定ではない。
